## Commands

- `npm run dev` — start the dev server at http://localhost:4321. For long-running work prefer `astro dev --background`; manage it with `astro dev stop`, `astro dev status`, `astro dev logs`.
- `npm run build` — production build to `dist/` (run before deploying)
- `npm run preview` — serve the built site locally
- `npx astro check` — typecheck the project (`@astrojs/check`, `typescript`, `@types/node` are installed)
- `npx astro add <integration>` — add an integration (e.g. `npx astro add tailwind`)
- **Caveat:** after editing `.astro` components while dev runs, restart the dev server before visual verification — Vite can serve stale scoped CSS. If `astro dev stop` reports no server while :4321 still responds, kill the PID from `lsof -nP -i :4321` and start fresh from the project root (a start from another cwd fails with "Missing pages directory").

## Architecture

**Approved stack (user-mandated):** Astro 7 (static site, SSG), HTML5, CSS3, vanilla JavaScript, GSAP for animations. PHP only if a backend is later required; MySQL only if a database is later required.

- **Do NOT add** React, Next.js, Tailwind, Bootstrap, or any other frontend framework unless explicitly instructed.
- **Do NOT use Stitch** (or other design-generation tools) for this project — design is done directly in this Astro codebase with Claude Code, based on user requirements.
- **File-based routing**: `src/pages/` — every `.astro` file is a route (`src/pages/index.astro` → `/`, plus `work.astro`, `services.astro`, `industries.astro`, `about.astro`, `contact.astro`, `privacy-policy.astro`, `terms-and-conditions.astro`).
- **Services page** (`src/pages/services.astro`) — the six brief titles as detailed rows (desc + "includes" chips are DUMMY copy) + a 5-step process strip + FAQ + CTA. **Industries page** (`src/pages/industries.astro`) — the nine brief industries as cards (blurbs DUMMY), three design rules (DUMMY) and a REAL client-name strip computed from `src/data/work.ts` captions.
- **Work page** (`src/pages/work.astro`) — portfolio gallery from `src/data/work.ts` (81 REAL photos grouped Engineering / Real Estate / Jewellery, client captions copied verbatim from the live site; the sector blurbs in work.ts are DUMMY copy until the user approves). Tiles are buttons feeding a vanilla-JS lightbox (Esc/←/→/backdrop close, scroll lock, focus restore) + FAQ section.
- `src/layouts/Layout.astro` — shared page shell (head, nav, footer); wrap every new page in it.
- `src/styles/global.css` — global styles, imported by the layout. Light theme by default (warm paper `--bg`, deep-teal ink `--ink`); photo-led sections (Hero, Industries, Final CTA) carry `.theme-dark` to keep light-on-dark ink. Section background tones: `.tone-white`, `.tone-tint`, `.tone-ink`, `.tone-accent`. `.prose` styles the legal pages' article text.
- `src/components/ui/PageHero.astro` — shared inner-page header (eyebrow + masked title lines + optional subtitle/photo). It carries the `data-hero-*` hooks, so `scripts/motion.ts` plays the standard hero entrance on every page that uses it; it also sets `id="top"` so footer/back-to-top anchors work. Legal pages omit the photo (teal glow backdrop) and use `compact`.
- `src/components/ui/PlaceholderImage.astro` — image wrapper: renders `<img>` when given `src`, else a neutral SVG motif. Handles aspect-ratio, tone, alt/aria.
- `src/components/sections/Faq.astro` — shared FAQ accordion (one panel open at a time; panels animate via the CSS grid-rows 0fr↔1fr trick; aria-expanded/controls/hidden wired). Props: `{eyebrow, title, intro?, items, tone?, id?}` — `id` prefixes the panel ids (`${id}-panel-${i}`), so pages with multiple FAQs must pass distinct ids. Used on Home/Services/Work with per-page DUMMY Q&A arrays defined in each page.
- **World map** (`public/images/world-map.svg`, ~400 KB) — dotted map in the homepage GlobalPresence section with the four markets highlighted: teal-tinted countries, pulsing markers, labels and dashed flow arcs (India/Japan/China/USA). The rest of the world is drawn as visible dotted coastlines/borders (`.land` stroke `#24464e` @ 0.6 opacity, dasharray `0.9 2.4`, width 1.4 — tuned so the dots read clearly on the paper background; don't thin them without re-checking pixel density). Generated by `/tmp/kalpataru-verify/make-world-map.mjs` from public @svg-maps/world geometry (MIT — not from any old Kalpataru project); re-run it to tweak markets/labels. The projection is Robinson-like, not lon/lat — marker positions are point averages inside each country's path (the USA path spans Alaska/Hawaii, so it filters to the contiguous mainland). Loaded via `<img>`, so the SVG carries its own hardcoded colors/fonts and a reduced-motion kill; on small screens the map scrolls horizontally (min-width 780px + "swipe" hint).
- **Nav links are home-aware:** `NAV_LINKS`/`FOOTER_NAV` in `src/data/site.ts` store section links as `/#locations` etc.; `Header.astro` and `Footer.astro` compute `const isHome = Astro.url.pathname === '/'` and strip the leading slash via `navHref()` while on the homepage. Work/Services/Industries/About/Contact are real routes; legal links (`LEGAL_LINKS`) render in the footer bottom bar.
- **Contact form** (`src/pages/contact.astro`) posts to the PHP backend at `/api/contact.php`: fetch + JSON with inline status messages, plus a no-JS fallback (plain form POST — the backend redirects back with `?sent=1` / `?sent=error`). Carries a honeypot `website` field and hidden `page` + `form_ms` inputs (anti-spam). The inline script must stay plain JS — no TS annotations.
- **PHP backend** (`backend/`) — Phase 1 of the CMS, deployed on Hostinger shared hosting (PHP 8 + MySQL) alongside the static site: `api/contact.php` (validates, stores leads in MySQL, emails `NOTIFY_EMAIL`; honeypot + minimum-time + per-IP rate limit via `form_submissions`), `admin/` (login-gated leads panel: filters, statuses, notes, delete, CSV export; styled with the site's Manrope/Inter fonts loaded from `/fonts/` — admin.css must keep the absolute `/fonts/` URLs since the admin lives at `/admin/`), `lib/` (config/db/helpers/auth/mail/leads; gitignored `config.local.php` overrides settings locally — it must stay ignored, the pattern is `backend/lib/config.local.php`), `sql/schema.sql`, `tools/hash.php` (bcrypt admin-password hash), `backend/README.md` (click-by-click Hostinger setup). Local end-to-end tests run against a merged dist/+backend/ staging copy at `/private/tmp/kalpataru-stage` served by `php -S 127.0.0.1:8081` with local MySQL `kalpataru`. Phases 2–4 (logo upload, cards CMS, testimonials/stats, GitHub auto-rebuild) build on this — not started yet.
- **Mobile sticky tab bar** (`Layout.astro` + `.sticky-cta` in global.css) — mobile-only bottom bar, **user-specified layout**: one row of 5 equal columns — Work / Services / Home / Contact Us / WhatsApp — each with an icon above a tiny label. The current page gets `.is-active` + `aria-current="page"` (teal accent); WhatsApp is built from `SITE.phone`. Hidden on desktop and while the mobile menu is open; `body` gets matching bottom padding. Styles live in global.css because the bar sits outside scoped components.
- **Button colour rule:** in `.theme-dark` sections the solid button turns white, so its text must stay ink-dark — `.theme-dark .btn.btn--solid { color: var(--ink-strong) }` in global.css. The class is **doubled on purpose**: single-class form ties with the scoped `.btn--solid[data-astro-cid-*]` selector, which wins by source order and produced white-on-white buttons (the Services-page CTA bug). Keep the doubling if you restyle.
- **About page** (`src/pages/about.astro`) — PageHero → story section → **DUMMY leadership section** (3 cards: Founder / Director / Creative Head with invented names+bios and silhouette placeholders `public/images/team-founder.svg` / `team-director.svg` / `team-creative.svg` — replace names in the page and photos by overwriting those files) → Stats → WhyKalpataru → CTA.
- **Motion wiring:** `src/scripts/motion.ts` owns GSAP (hero entrance keyed off `[data-hero-media]`, scroll reveals on `[data-reveal]`, stat counters on `[data-stat]`, masked headline reveals on `.section-head__title`/`[data-headline]`, auto rise of `.section-head` children, and parallax on full-bleed media only — `.hero__media`, `.industries__bg`, `.cta__media`). **No image motion anywhere (user-mandated):** `[data-img-reveal]` wipes/zooms were removed — do not re-add them. Masked titles split child nodes at `<br>` into `.title-mask > .title-mask__line` spans (classes live in global.css; inline spans like `.cta__period` survive the split). `main.ts` owns header scroll state, mobile menu, service/industry hover interactions. Both must tolerate missing elements without console warnings (inner pages reuse the homepage selectors).
- `public/` — static assets served at the root: `images/` (photos incl. real portfolio shots), `videos/` (hero.mp4), `brand/` (user logo), favicon, `fonts/` (self-hosted **Manrope** display + **Inter** text woff2, latin + latin-ext; declared in global.css — no font CDN). Add brand assets here.
- `astro.config.mjs` — Astro config; `tsconfig.json` — TypeScript config.
- Pure `.astro` components — no JS framework installed. Node >= 22.12 required.
